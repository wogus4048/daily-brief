# 공모전 수집 역할 나누기 설계

상태: 2차 초안(2026-11-05). 냉정 리뷰(`docs/archive/review-2026-11-04-contest-collection-disposition.md`)와 사용자 결정("권고대로 반영")을 넣었다. 사용자 승인 전에는 코드를 바꾸지 않는다. `2026-11-04-claude-daily-brief-design.md`에 덧붙는 세부 문서다.

## 목표 줄

사용자 말에서 온 요구만 번호를 붙인다.

1. 정보력: "일단 가장 중요한건 정보력이야". 놓치는 공모전을 줄인다.
2. 역할 나누기: "알게된곳은 어떤워커한테 조사하게시키고 어떤 워커한테는 우리가 이미 찾은곳제외 자유롭게 시키고 새롭게 알게되면 또 저장해놓고".
3. 조사 탭 정리: "찾기위해 열어놓은탭들 왜 다 안닫혀", "조사탭닫게 개선도해놨어?".

완료 조건: 예약 실행 1회에서 아는 곳 수집과 자유 탐색이 모두 돌고, 자유 탐색 결과가 후보로 들어가고, 새 목록 페이지가 조사 기록에 남고, 실행 뒤 조사 탭이 남지 않는다.

항목 수: 목표 3개, 범위 밖 3개.

## 측정 근거

전부 `docs/archive/titan-score-2026-11-04.md`의 기록이다. 세 실행 모두 1회씩이라 재현성은 모른다.

| 실행 | 방식 | 낸 공고 | 정답 19건 중 | 새 공식 확인 | 시간 |
|---|---|---|---|---|---|
| 1차 | 일반 채팅, 출처 지정 없음 | 35건 | 8건 | 22건 | 2분 35초 |
| 2차 | worker 2개, 출처 지정 | 36건 | 11건 | 4건 | 약 22분 55초 |
| 3차 | 일반 채팅, 아는 사이트 제외 | 20건 | 3건 | 6건 | 9분 57초 |

- 2차는 1차의 공식 확인 22건 중 8건을 놓쳤다.
- 2차 포털 순회 worker는 18분을 쓰고도 포털 3곳의 끝 페이지에 못 갔다. 목록을 "등"으로 줄여 정답 1건이 보고에서 빠졌다. 탭 32개를 열고 하나도 닫지 않았다.
- Claude 자체 자유 탐색은 같은 조건으로 재지 않았다. 사용자가 비교 없이 Titan으로 정했다.

## 구조

매일 실행은 세 갈래가 하나의 후보 목록으로 모인다.

1. 크롤러가 아는 곳을 읽는다.
2. 자유 탐색이 아는 곳을 뺀 나머지를 찾는다.
3. 주 실행이 후보를 공식 페이지로 확인하고, 새 목록 페이지를 기록한다.

## 변경 항목

각 항목 끝의 번호는 채우는 목표다.

### 1. 아는 곳은 크롤러가 맡는다 [1, 2]

재설계 문서 항목 1을 그대로 쓴다. 포털 순회 worker는 쓰지 않는다. 근거는 위 2차 기록이다. 크롤러가 못 읽는 곳만 Claude 하위 에이전트의 브라우저 읽기로 넘긴다. 크롤러는 콘테스트코리아를 끝까지 읽고 위비티도 읽는다. 측정값은 전체 설계의 "정보력 측정 결과"에 있다.

### 2. 자유 탐색은 일반 채팅 1회로 한다 [1, 2]

`prepare` 뒤에 Titan Prime 채팅을 열어 worker로 자유 탐색을 돌린다(사용자 결정 "worker 써야지").

- 호출: 고정 스크립트가 Titan `/v1/sessions/open`으로 지시문을 보내고, 답을 파일로 저장하고, 채팅 탭을 정리한다. 호출 방식은 네이버 프로젝트 `scripts/titan_prime_probe.py`를 참고한다.
- 자유 탐색이 실패해도 발행을 막지 않는다. 조사 기록에 성공·부분 성공·실패와 건수, 사유를 남긴다. 누락 측정이 실패한 날을 가려야 하기 때문이다.

### 3. 제외 목록은 파일에서 만든다 [2]

지시문의 제외 사이트는 사람이 적지 않고 `data/crawler-sources.json`의 `active`에서 만든다. 제외는 사이트 단위로 한다. 공고 단위로 빼면 지시문이 매일 길어지고, 내용이 바뀐 공고를 다시 볼 기회도 없어진다.

끝까지 읽었다는 기록이 없는 사이트까지 뺄지는 전체 설계의 질문 3에 달렸다.

### 4. 자유 탐색 답변은 후보일 뿐이다 [1]

답변의 공고는 재설계 항목 2의 후보 처리로 넘겨 공식 페이지로 확인한다. 3차 답변의 마감일 중 2건은 공식 페이지에서 확인되지 않았다. 지시문에는 다음 두 줄을 넣는다.

- 공고를 줄이지 말고 전부 적어라. 2차에서 줄여서 공고가 사라졌다.
- URL은 코드 블록에 평문으로 적어라. 1차에서 Titan 기록에 링크가 남지 않았다.

### 5. 새로 알게 된 목록 페이지를 기록한다 [2]

새 저장소를 만들지 않는다. 기존 수명주기를 쓴다.

- 자유 탐색이 알려 준 목록 페이지를 주 실행이 열어 보고, 공모전이 반복해서 올라오는 공개 목록이면 조사 기록의 `sourceDiscoveries`에 적는다(`AUTOMATION.md:225`).
- `crawlerSpec`까지 함께 적는다. spec이 없으면 `NEEDS_SPEC`에 머물러 크롤러가 읽지 않는다(`evolve_crawler_sources.py:166-168`).
- 목록마다 고유 `key`를 적는다. 없으면 도메인으로 키를 만들어 같은 사이트의 두 번째 목록이 저장되지 않는다(`:140`, `:164`).
- 그 뒤는 `NEEDS_SPEC -> SHADOW -> ACTIVE` 흐름과 `data/crawler-sources.json`의 승격 기준이 맡는다.
- 한 건짜리 공고 주소는 적지 않는다.
- ACTIVE가 된 곳은 항목 3에 의해 다음 자유 탐색의 제외 목록에 자동으로 들어간다.

### 6. 탭이 남지 않게 한다 [3]

실패 종류: worker가 연 일반 탭의 정리 책임자가 없다. worker가 끝나면 소유권 때문에 아무도 닫을 수 없다.

Daily Brief도 worker를 쓰므로 근본 수정이 필요하다. 구현은 Titan 브랜치 `feat/worker-tab-cleanup-20261105`에 있고 재설치 전이다.

- 근본 수정(Titan): worker의 채팅 탭이 닫힐 때 그 worker가 연 탭을 닫는다(사용자 결정 "채팅 탭 닫힐 때"). `finish`는 끝이 아니라 잠듦이라 그 시점에는 닫지 않는다(`agents-finish.ts:99`, `agents-sleep.ts:47,51`). 고칠 곳은 처분표 발견 9~12에 있다. 규모는 추정 수십 줄이고 재지 않았다. 설계할 때 냉정 리뷰를 다시 받는다.
- 전제: 설치본은 commit `35026c452f87`(dirty)이고 소스 HEAD는 `0ca6b289`라 먼저 맞춰 봐야 한다. Titan 재빌드와 재설치는 사용자 승인이 필요하다.
- 임시: worker를 쓸 때 지시문에 "끝내기 전에 연 탭을 `browser_tabs` close로 닫아라"를 넣는다. worker 판단에 기대므로 근본 수정 전까지만 쓴다.
- 확인: 일반 탭은 `/v1/status`의 `openChatTabs`에 안 잡힌다. 탭 수 확인은 `browser_tabs` list로 해야 한다.

## 테스트

목표 동작마다 하나다.

- 제외 목록이 `active`와 모음 사이트에서 만들어진다 [2].
- 자유 탐색이 실패해도 `publish`까지 간다 [1].
- 자유 탐색 후보가 공식 확인 단계로 넘어간다 [1].
- 새 목록 페이지가 `sourceDiscoveries`에 기록된다 [2].
- Titan 수정 뒤 worker 채팅 탭이 닫히면 자기가 연 탭이 닫히고 다른 탭은 남는다 [3].

## 구현 전에 확인할 것

- 예약 시각에 Titan과 전용 크롬이 켜져 있는지.
- 예약 실행에서 Titan 토큰 파일을 읽어도 되는지.

## 범위 밖

- 공모전 중복 판정과 내용 갱신 자동화. 사용자가 후순위로 정했다(`docs/BACKLOG.md`).
- Claude 외부 prime의 브라우저 바인딩 변경. worker를 쓰지 않는 한 필요 없다.
