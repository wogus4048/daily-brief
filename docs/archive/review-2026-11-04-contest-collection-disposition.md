# 공모전 수집 설계 리뷰 처분표 (2026-11-04, 2판)

목표 항목 3개, 범위 밖 2개. 발견 12건: 반영 8건, 일부 반영 2건, 범위 밖 2건.

리뷰어: Titan Web GPT 일반 채팅(원문 `review-2026-11-04-contest-collection.md`). 리뷰 비용은 3분 50초, Titan 추정 약 83,110 토큰이다. 설계에는 아직 반영하지 않았고, 사용자 답을 들은 뒤 반영한다.

## 1판에서 틀린 것

사용자가 "제대로된 처분이야?"라고 물어 코드로 다시 확인했다. 1판은 제대로 된 처분이 아니었다.

- 발견 4는 기각이 틀렸다. 같은 도메인의 두 번째 목록 주소는 저장되지 않는다.
- 발견 1은 "기록"만으로 부족했다. 끝까지 읽는 기능이 없어서 기록할 것이 없다.
- 발견 2는 처분 근거가 추정이었고, 지시문으로 페이지 단위 제외를 시킬 수 없다는 점을 놓쳤다.
- 발견 8의 근거 `evolve:331`은 처분 근거가 되지 못했다. 발견 3을 반영하면 주 실행이 spec을 쓰게 되기 때문이다.
- 발견 9는 새 권한 경로가 필요 없을 수 있다.
- 발견 11은 리뷰어와 나 모두 핵심을 놓쳤다. worker의 finish는 끝이 아니라 잠듦이다.
- 발견 12의 처분 확인 칸이 추정이었다. 규칙상 내면 안 되는 처분이었다.
- 첫 줄의 "범위 밖 0개"가 틀렸다. 깨지는 목표가 없는 발견은 표에 처분으로 넣지 않고 범위 밖으로 둬야 한다.
- 리뷰어의 "깨지는 목표" 답을 근거 표시 없이 "없음"으로 바꿨다. 이번 판은 바꾼 칸을 표시했다.

## 리뷰 뒤 내가 추가로 찾은 것

- 확장의 탭 한도는 브라우저당 32개다(`extension/browser-control.js:6,212,504`). 2차 worker-1은 정확히 32개를 열었다. 사용자가 탭을 닫으면 `detached`가 기록을 지운다(`:622-624`). 실제로 막힌 기록은 없다(`app.log` 최근 3,000줄에 `BROWSER_TAB_LIMIT` 0건).
- 3차 일반 채팅은 `browser_tabs`를 쓰지 않았다. Claude 하위 에이전트 쪽 탭 생성은 확인 전이다.

## 재리뷰

발견 9의 대안, 발견 11의 잠듦 문제는 리뷰어가 보지 않은 내용이다. Titan 탭 수정을 실제로 설계할 때 냉정 리뷰를 다시 받는다. 지금은 Titan 연결이 끊겨 있어(ECONNREFUSED) 같은 리뷰어를 쓸 수 없다.

## 사용자만 답할 질문

질문 1~3은 리뷰어가 분류한 것이고, 질문 4는 코드 확인으로 내용을 바꿨다.

1. 이미 수집한 사이트도 끝까지 읽었다는 기록이 없으면 자유 탐색이 다시 보게 할까.
2. Claude와 Titan을 같은 조건으로 비교한 뒤 신규 공식 확인 수와 운영 안정성으로 실행 주체를 고를까.
3. 자유 탐색이 실패한 날 정상 발행할까, 불완전 표시를 남기고 발행할까.
4. worker가 만든 탭을 언제 닫을까. 사용자 결정(2026-11-05): "채팅 탭 닫힐 때". 그래서 worker를 쓰는 실행은 끝에 채팅 정리까지 해야 조사 탭이 닫힌다.
