# 냉정 리뷰: 조사와 작성을 GPT worker로 옮기는 설계 (2026-11-09)

리뷰어: Sonnet 하위 작업, 읽기 전용. 비용: 210,968 토큰, 약 9분 20초, 도구 51회.
대상: `docs/superpowers/specs/2026-11-09-gpt-research-design.md`.

## 숫자 재집계
- 맞음: 공식 확인 43건 705.8초, 자유 탐색 406.1초, 재확인 55건(통과 42, 실패 13), 트랙 후보 89건, 게시 14건, REQUIRED_SOURCES 17곳, 실행 31.6분.
- 틀림: "worker 동시 3개". 지금 Titan 설정 `multiAgent.maxWorkers`는 2이다(`config.json`, 11-09 12:55). 작성자가 직접 확인했다. app.log 13:05에 "the limit set in the app is 2"가 남아 있다. 11-05에는 3이었다.
- 미확인: Claude 하위 작업 83만 토큰. 근거는 작업 완료 알림의 subagent_tokens 합계다(102k+145k+126k+35k 보충+273k+150k).

## 발견 (요약, 원문은 대화 기록)
1. 공식 확인을 못 한 공고가 NOT_RELEVANT로 기록되면, `earlier_decisions` 때문에 14일 동안 다시 확인되지 않는다. 목표 5, 6.
2. 매년 열리는 대회의 새 회차가 CLOSED 기존 카드와 같은 공식 URL이라 "이미 있음"으로 빠진다. 목표 5.
3. 묶음 크기가 worker 3개 기준(15건)인데 한도는 2다. 11-09에 답이 빠진 10건의 원인이다. 목표 6.
4. Titan 한도는 run 단위이고 전체 한도는 꺼져 있어, Prime 채팅을 동시에 여러 개 열 수 있다(병렬 안정성은 미확인).
5. 검사기 필수 칸 가운데 설계가 출처를 정하지 않은 것이 있다. 축 이름, 고정 출처의 정확한 키, EXHAUSTED 판단과 사유, DACON 재고(프로그램이 채워야 함), 새 카드 id·날짜 덮어쓰기, 재확인 실패의 primarySourceUrl. 목표 4.
6. 재확인 changes에 `deadline`이 없다. 연장 공고가 옛 날짜로 닫힌다. 목표 1.
7. "검색으로 확인되면 열지 마라"는 지시와 AUTOMATION의 "공식 페이지를 연다"가 충돌한다. 목표 1.
8. 찾기·뉴스의 기록 줄(queries, fixedSource, district)은 번호가 없어서 빠져도 다시 보낼 수 없다. 조립이 실패하면 발행이 없다. 11-04 결정("자유 탐색 실패해도 발행")과 충돌한다. 목표 4, 6.
9. Titan worker 메시지는 4,000자 제한이다. json 블록이 메시지 두 개에 걸치면 깨진다. 메시지마다 블록을 닫게 해야 한다. 줄 단위 중복 제거도 필요하다. 지시문도 4,000자 제한이다. 목표 4, 6.
10. 재전송 묶음은 번호를 새로 매기므로 원래 번호로 되돌리는 매핑이 필요하다. "확인불가" 줄은 받은 것으로 친다. 목표 6.
11. 프로그램의 후보 고르기는 사이트마다 제목이 다른 중복(숭실대, LG)을 못 잡는다. 11-09 손 처분 16건 중 5건이 중복이었다. 목표 4.
12. "표 형식이라 Claude가 필요했다"는 전제는 반만 맞다. Claude가 한 일은 범위·중복·처분 판단과 카드 쓰기였다.
13. 뉴스·디스커버리 카드의 정책(커뮤니티 근거 등)은 검사기가 보지 않는다. 목표 3.
14. 시간 예상 "약 1시간"은 낙관값이다. 70~110분일 수 있다(추정).
15. 실제 시험의 비교 기준(89건)은 기존·마감까지 포함한 숫자다. "접수 중이고 범위 안인 공고" 기준으로 비교해야 한다. 목표 5.
16. `nextCandidates` 114건은 대부분 도메인 루트다. 몇 건을 넣을지 기준이 없다. evolve는 GitHub 워크플로라 `all` 안에서 돌지 않는다. 정기 대회 목록을 지난 발행본에서 뽑으면 놓친 대회는 들어가지 못한다. 목표 5.
17. 예약 Claude가 한 시간짜리 실행을 기다리는 방법이 없다. 도구 한 번 호출은 10분이 한도다. 목표 4.

## 사용자만 답할 질문 (리뷰어)
1. 정기 대회 목록에 넣을 대회.
2. GPT 단계가 일부 실패한 날 발행을 막을지, 부분 발행할지.
3. 공식 확인을 못 한 공고를 다음 날 다시 확인할지.
4. Titan worker 한도를 3으로 올릴지, Prime 채팅 병렬을 허용할지.
5. GPT가 쓴 카드를 사람이 안 보고 바로 올려도 되는지.
6. 실제 시험의 합격 기준.
7. 시작 점검이 Titan 앱과 크롬을 자동으로 켜도 되는지.
