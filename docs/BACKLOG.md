# 남은 작업과 후속 계획

2026-10-08 정리. 완료 표시에는 실제 실행·검증 근거를 남긴다. 수집 지침 반영, 코드 구현, 실제 콘텐츠 발행은 서로 다른 상태다.

## P0 — 예약 갱신 복구와 첫 정상 발행

- [ ] **ChatGPT 예약 문구 교체·재개 확인** — 사용자 작업. [교체 문구](chatgpt-task-prompt.txt)를 저장하고 매일 09:00 Asia/Seoul 설정을 확인한다. 마지막 확인은 중지 상태이며 이후 재개 여부는 미확인이다. 저장소 수정으로 예약이 재개되지는 않는다.
- [ ] **새 기준으로 수동 갱신 1회 실행** — 오늘자 필수 cache를 사용해 모든 조사 트랙을 수행한다. 네 신규 shadow 출처도 후보로 검토한다. 자료 날짜만 바꾸거나 audit을 꾸며 만들지 않는다.
- [ ] **발행까지 확인** — 세 파일만 포함한 staging branch, evidence gate, main 승격, Pages 성공과 실제 사이트의 발행 날짜·신규 내용까지 확인한다. 정리 시점의 발행 날짜는 2026-10-07이다.
- [ ] **다음 예약 주기 확인** — 사전 수집, 09:00 조사, 10:37 상태 점검이 이어지는지 확인한다. 비필수 출처 실패와 필수 수집·발행 실패를 구분해 판단한다.

## P1 — AI Discovery 화면과 데이터 구조

- [ ] **분류 구조 확정 및 스키마 정리** — 용도, 도구 형태, 출처, 주목도를 별도로 표현한다. 안정적인 카테고리 ID·이름·상위 관계를 두고, 순환·중복·존재하지 않는 상위 분류를 검증한다. 기존 `categories[]` 및 `discoveryType`과의 호환·이관 방법을 정한다.
- [ ] **계층형 카테고리 필터** — 영상 아래 쇼츠, 에셋 아래 2D·3D. 상위 선택은 모든 하위를 포함하고, 하위 선택은 범위를 좁힌다. 한 자료의 복수 분류를 지원한다.
- [ ] **확장 가능한 탐색 UI** — 카테고리를 화면 코드에 고정하지 않고 검증된 분류 데이터에서 읽는다. 카테고리가 늘어도 모바일·데스크톱에서 검색·선택·초기화가 편해야 한다. 모든 칩을 무제한 나열하지 않는다.
- [ ] **형태별 탐색** — MCP·플러그인·프롬프트·스킬·에이전트·사이트·워크플로 등. GitHub 출처 필터 및 용도와 교차 선택할 수 있어야 한다.
- [ ] **스테디셀러·트렌딩·신규 발견** — 스테디셀러와 트렌딩이 동시에 가능하도록 표현한다. 기존 awareness/trend/newsState와의 관계를 명시하고, 누적 별 수만으로 트렌딩을 판정하지 않는다.
- [ ] **기존 8개 자료 재분류 및 카드 보완** — 실제 용도, 사용 환경, 진입 링크, 비용·제약, 선정 근거를 확인한다. 코드 변경만으로 조사하지 않은 사실을 채우지 않는다.

완료 조건: 기존 자료 호환, 복수·상하위 분류, 필터 조합·초기화·빈 결과, 모바일 가독성, 과거 스냅샷 표시를 검증하고 배포 화면을 확인한다.

## P1 — 넓어진 공모전·창업지원 범위와 실제 수집 정합성

- [ ] **기존 크롤러의 후보 추림 조건 점검** — AUTOMATION.md는 넓어졌지만 기존 크롤러의 키워드·제외 조건까지 전부 재작성한 것은 아니다. Grantly, K-Startup 등에서 아이디어 대회, 일반 개발 대회, 미등록 신청 가능 트랙과 모두의창업 같은 모집형 프로그램을 놓치는지 실제 목록과 대조한다.
- [ ] **사업자 요건 구조화** — 신청 시 필수/선정 후 필요/미등록 가능/불명확을 구분하고 혼합 트랙을 표시한다. 지역·나이·재직 조건은 임의 제외 대신 명확히 표시한다.
- [ ] **누락 사례 회귀 검사** — AI와 무관한 아이디어 공모전, 소액·무상금 대회, 프로그램 개발 대회, 현금지원 없는 창업교육, 미등록 트랙, 선정 후 등록 사업이 살아남는지 검사한다.

## P2 — AI 뉴스 증거와 콘텐츠 품질

- [ ] **인기 글 근거의 구조 검증** — 현재 communityEvidence, verificationUrls, verificationNote는 지침으로 요구하지만 validator가 해당 추가 필드를 강제하지 않는다. 적용 시작일/버전을 두고 신규·갱신 뉴스부터 필요한 링크·시각·인기 근거를 검증한다. 과거 audit에 소급해 허위 근거를 채우지 않는다.
- [ ] **새 수집 방식으로 실제 뉴스 발행·검수** — 인기 글, 사용기, 논쟁, 실험을 포함하되 사실과 의견, 사건 날짜와 토론 날짜를 구분한다. 중복 주제는 기존 항목에 연결한다.
- [ ] **뉴스 카드·상세의 출처 표현** — 필요한 경우 커뮤니티 글과 원문, 왜 화제인지, 확인 시각을 읽기 쉽게 표시한다. 지침 변경만으로 현재 카드가 이를 모두 표시하는 것은 아니다.

## P2 — 출처 확대와 운영 검증

- [ ] **네 SHADOW 출처의 일별 관찰** — 연결 성공 외에 실제 유용 후보·발행 기여를 audit에 기록하고 기존 기준에 따라 정식 편입한다. 편입을 위해 임의로 점수·횟수를 올리지 않는다.
- [ ] **범위 확장 후보 조사** — MCP·플러그인·프롬프트 목록, 디자인·이미지·영상·글쓰기 도구, 2D·3D 에셋 출처를 추가 검토한다. 공개 API/RSS/HTML 방식, 링크·날짜·중복·화제성 근거, 실제 유용성, 접근 제한을 검증한 뒤 등록한다. 아직 자동 수집 중이라고 간주하지 않는다.
- [ ] **GeekNews·Devpost 접근 상태 점검** — 각각 WATCH_ONLY와 실패 기록 상태를 유지하고 허용된 공식 접근 경로나 편집 조사 대안을 확인한다. 차단을 우회하지 않는다.
- [ ] **운영 관측 개선 검토** — shadow 출처별 상태와 실제 발행 기여를 더 쉽게 볼 수 있도록 개선한다. 크롤러는 실행되지만 연구가 멈춘 상태를 별도로 드러낸다.
- [ ] **날짜 내 보완 실행 정책 검토** — 현재 lifecycle은 같은 연구 날짜를 한 번만 평가한다. 같은 날 늦게 추가된 근거를 반영할 필요가 생기면, 성공 횟수는 늘리지 않고 근거만 병합하는 방법을 별도 설계한다.

## P3 — 문구와 작업 디렉터리 정리

- [ ] 미커밋 한국어 편집 원칙과 Discovery 문구를 검토한다. 과거 archive를 단순 윤문으로 바꾸지 않는 정책과 충돌하지 않게 처리한다.
- [ ] 미추적 Pretendard 폰트·라이선스의 사용 여부를 확인해 보존 위치 또는 제거 여부를 결정한다. 현재 실제 적용 폰트는 Wanted Sans다.

## 권장 실행 순서

1. 예약 문구 교체·재개 → 실제 조사·발행 1회 확인.
2. Discovery 스키마·계층형 필터·카드 구현 및 기존 자료 재분류.
3. 기존 기회 수집 필터의 범위 누락 점검과 AI 뉴스 근거 검증 강화.
4. 며칠간의 출처별 실적을 확인하고 새 분야의 출처를 순차 확장.

지금 단계에서는 이미 승인된 분류 방향을 바탕으로 작업하되, 새로운 데이터 구조의 호환성과 실제 자료의 근거를 확인한다. 예약 접근, 사이트 차단, 조사 증거 부족을 코드 수정만으로 해결한 것으로 처리하지 않는다.
